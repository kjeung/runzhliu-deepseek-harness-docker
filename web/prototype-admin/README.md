## 本次验证的问题

> “管理页的最小可用交互是什么样的？”（#6）

本原型采用 UI 分支（“它应该长什么样？”）。状态与逻辑的“答案”已在规格
（#13 supervisor 状态、#14 版本策略引擎、#16 失败/回滚决策）中约定：本
页面只是**消费引擎的响应，不重复过滤/比较逻辑**。3 个结构上完全不同的
方案，挂在同一个路由上，通过 URL 参数切换。

## 运行方式

```bash
node web/prototype-admin/serve.cjs
# → http://127.0.0.1:8787/prototype-admin/index.html?variant=A
```

- 默认 `?variant=A`。
- 切换方案：底部悬浮条（← / 方案名 / →）或键盘 ←/→（输入框聚焦时不生效）。
- 每个方案的 URL 可以分享并稳定于刷新。
- 无持久化：所有状态都在内存里；刷新页面即回到默认 `starting` 状态。

## 三个方案的取舍

| 键 | 布局 | 主要交互 | 适用场景 |
|---|---|---|---|
| A | 单列：顶部状态条 + 标签页（版本 / 安装日志 / npm 源 / 关于） | 顶部状态条 + 标签切换 | 最少的页面；默认运维视图 |
| B | 固定左侧边栏（系统状态 / 安全 / 关于）+ 主内容区 | 侧边栏导航；主区放“当前版本”卡片 + 版本列表 | 未来管理功能增多时的导航模型 |
| C | 纯会话式：一条主时间线，内嵌“操作 → 响应”块，无标签、无侧栏 | 时间线追加条目 | 把管理动作当作可审计的事件流 |

## 已约定的决策（记录在此，供实现时回填）

- 默认展示状态：`starting`（supervisor 状态机的入口状态）。
- 安装确认：仅**未测试版本**需要二次确认；已测试（== pin）免确认。
- 页面绝不展示：launch token、完整日志原文（只展示脱敏摘要）、凭据。
- 页面不做登录，仅显示“由外部入口保护（SSO 在容器外）”。

## 状态模型（与 #13/#14/#16 对齐）

- Supervisor 状态：`starting → ready | token-timeout`，`exited(code)`；
  显式停止重置为 `starting`。
- 版本行（消费 #14 引擎输出）：version / prerelease 通道 / dist-tag 命中 /
  已测试(==pin) / 可安装+原因（pairing-missing 不可安装）。
- 安装/回滚/重置（消费 #16 决策输出）：lock（单锁冲突拒绝）、preflight
  （owner/space/registry 短路）、失败态可回滚（current 符号链接回翻）、
  重置仅移动（.retired），永不删除。
- 所有“动作”按钮驱动的是**桩状态机**（内存），不是真实后端。
